## 目标

按《素材类别分析模型对接说明》完成前端对接:素材类别编辑时绑定 AI 分析模型(提供商编码 + 模型编码),列表展示已绑定模型,并按 §4 调整模型编码唯一性提示。后端契约已在 `../courseware-workspace` 核对确认(`AiModelController#options`、`MaterialCategoryVO` 四个新字段、`MaterialCategoryUpdateDTO` 两个新字段、删除拦截文案、"该提供商下模型编码已存在" 文案均已在源码中核实)。

## 变更文件(6 个,均在当前前端仓库)

**1. `src/modules/ai/types/model.ts`** — 新增下拉选项类型,与后端 `AiModelOptionVO` 逐字段对齐:
```ts
export type AiModelOption = {
  id: number;
  providerId: number;
  providerCode: string | null;   // 提供商记录缺失时为 null
  providerName: string | null;
  modelCode: string;
  displayName: string;
  enabled: boolean;
  available: boolean;            // 模型启用 && 提供商启用
};
```

**2. `src/modules/ai/api/model.ts`** — 新增 `getAiModelOptionsApi = () => aiHttp.get<AiModelOption[]>('/model/options')`(实际 `/api/ai/model/options`,权限 `ai.model.query`)。

**3. `src/modules/material/types/materialCategory.ts`**
- `MaterialCategory` 增加 `aiProviderCode`、`aiProviderName`、`aiModelCode`、`aiModelName`(均为 `string | null`,来源为 `MaterialCategoryVO`)。
- `MaterialCategoryUpdate` 增加 `aiProviderCode: string | null`、`aiModelCode: string | null`。

**4. `src/modules/material/views/materialCategory/components/CategoryRuleDialog.vue`**(核心)
- 在「AI 分析」开关下新增「分析模型」表单项(`el-select` + `filterable` + `clearable` + `el-option-group` 按提供商分组,选项标签 `displayName（modelCode）`)。
- 表单模型增加 `aiProviderCode` / `aiModelCode` 两个字段;select 通过 `computed` 的 get/set 与 `${providerCode}::${modelCode}` 组合键互转(清空即置 null),避免下发时再做字符串解析。
- 选项来源:`/ai/model/options` 中 `available === true` 的项;若当前类别已绑定但模型/提供商已停用,额外保留该项并标注「已停用」;若绑定的模型已不存在(悬空引用),用类别自身的编码/名称合成一条「已失效,请重新选择」的项,避免选择被静默清空。
- 懒加载:弹窗打开时仅当类别已开 AI 或已绑定模型才请求;开关首次打开、或下拉首次展开时再补请求。请求失败置 `modelLoadFailed`,表单项内联提示「AI 模型列表加载失败,请确认已获得 ai.model.query 权限」,不重复弹全局错误。
- 校验:新增 `aiProviderCode` 规则——开关开启时必选,提示「启用 AI 分析时必须选择分析模型」(与后端文案一致);开关 `change` 时 `validateField` 即时反馈。`validateConditionalFields()` 追加:仅在选项加载成功时校验绑定项是否仍存在,失效则提示「当前绑定的分析模型已失效,请重新选择」。
- 提交:payload 追加 `aiProviderCode` / `aiModelCode`(始终成对下发)。**按你的选择,关闭开关仍保留已选模型并继续下发两个编码(引用保留),需要解除引用时用下拉的清除按钮清空**,提示文案写明这一点(「关闭开关不会解除引用;清除选择后模型才允许删除」)。
- 开关提示语由「仅保存开关,本期不触发 AI 分析任务」调整为「仅保存开关与模型绑定,本期不触发 AI 分析任务」。

**5. `src/modules/material/views/materialCategory/index.vue`** — 「AI 分析」列由 `width: 110` 调整为 `minWidth: 200`,单元格在原有已开启/未开启标签下增加一行模型信息:有 `aiModelName` 时显示 `模型名 · 提供商名`,仅编码存在(悬空)时显示 `编码 · 提供商编码（已失效）`,未绑定则不显示。

**6. `src/modules/ai/views/model/components/ModelDialog.vue`** — 按 §4,在「模型编码」输入下补充提示「同一提供商下唯一,不同提供商可使用相同编码」(新增轻量提示样式,不改动其他字段与提交逻辑;唯一性冲突仍由后端 `C1001` 与请求层统一提示)。

## 需要说明的契约与权限要点

- 实际 URL 为 `/api/ai/model/options`,返回排序为 `sort ASC, id DESC`,含停用模型;对接文档示例里的 `"code": 200` 与源码不符(实际为 `"0000"`),前端按现有请求层处理,无需特殊适配。
- 素材类别编辑页操作者除 `material.category.update` 外还需 `ai.model.query` 才能加载下拉;列表展示直接复用类别查询接口的新字段,不需要额外权限。
- 后端只校验模型存在性、不校验启用状态,因此前端限制为 `available=true` 可选项属于更严格的界面约束,不会造成保存被拒。
- 无需后端配合改动,无 DDL、无配置或环境变量变更。
